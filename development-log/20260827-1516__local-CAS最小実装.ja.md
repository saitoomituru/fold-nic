## 目的・非目標

- 目的: byte列をCIDv1／raw codec／SHA2-256で同定し、専用rootへatomic publishするlocal CASを作る
- 非目標: manifest persistence、署名、P2P共有、HTTP取得、private cache暗号化、総容量quotaを完成させない

## 入出力・副作用・権限

- 入力: callerが明示したbyte列、専用CAS root、object size上限
- 出力: CID、size、deduplicate結果、検証済みbyte列
- filesystem副作用: CAS root配下の`objects/<shard>/<cid>`と短命temporary file
- network: runtime networkなし。dependency取得時のみ
- authority: content identityのbyte一致だけを検査し、publisherや安全性を判定しない
- secret境界: private／secret objectの投入を防ぐ機能は未実装。取得物を自動実行しない

## `[FACT]` 事実・観測

- object pathはcaller入力pathではなくCIDからのみ生成する
- temporary fileは同一directoryへ作り、hard linkで既存objectを上書きせずpublishする
- read時にCIDを再計算し、既存file改変を検出する
- Unix環境ではdirectory `0700`、temporary object `0600`を要求する
- 初回の`multihash-codetable = "0.1"`指定はyank済み間接dependencyを選んだため、現行`0.2.2`へ補正した
- 初期profileに不要なhash実装を組み込まないようdefault featureを無効化し、`sha2`だけを有効化した

## `[INTERPRETATION]` 考察

- object単位size上限とCAS root confinementは成立するが、総容量quotaは別に必要
- hash一致は安全性や再配布権限を意味しないため、HTTP guardとKamiiを後続へ分離する
